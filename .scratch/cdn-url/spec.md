# cdn-url 规格

Status: ready-for-agent

## Problem Statement

我手上的 GitHub 文件地址（规则集、配置片段、release 资产、仓库打包）在国内网络经常拉不动。可用的加速服务有一堆，但每一家的地址语法都不一样：有的把 `owner/repo@ref/path` 重排进路径，有的只是把原地址拼在自己域名后面，有的还必须去掉 `https://`。更麻烦的是支持范围不同——把 gist 地址交给 jsDelivr 一定是 404，把 release 资产交给它也一样。手工拼地址既要记语法，又要记每家能吃什么，拼错了还得先怀疑是服务挂了。

## Solution

一个纯静态网页：粘贴一行或多行 GitHub 源地址，每条源地址给出一张卡片，卡片里列出所有**真正能服务这条源**的加速地址，每行可单独复制、可打开验证。页面上同时能查到每个服务支持哪些源类型、以及某条地址为什么被拒绝。不需要安装、不需要登录、不需要后端。

## User Stories

1. 作为使用者，我想一次粘贴多条源地址，这样我不必为每个文件重复操作。
2. 作为使用者，我想每条源地址单独成一张卡片，这样我能确认每一条都被处理了、没有静默丢失。
3. 作为使用者，我想卡片里只出现能服务这条源的服务，这样我不会去点一个注定失效的地址。
4. 作为使用者，我想一键复制单条加速地址，这样我能直接粘进配置文件。
5. 作为使用者，我想一键复制整张卡片的全部地址，这样我能一次把一条源的备选地址全部灌进配置。
6. 作为使用者，我想一键复制页面上所有地址，这样批量处理多个文件时不用逐个点。
7. 作为使用者，我想每条结果旁边有打开按钮，这样我能自己判断它是否可用，而不依赖工具给出的可疑信号。
8. 作为使用者，我想在结果行上看到该服务的支持范围标签，这样我知道这家除了当前这类源还能干什么。
9. 作为使用者，我想在页面底部看到完整支持矩阵，这样我能查清某个服务为什么没出现在某条源的结果里。
10. 作为使用者，我想粘贴 `tree` 目录页时得到明确拒绝和原因，而不是一个看起来能用的错误地址。
11. 作为使用者，我想粘贴非 GitHub 域名时被明确拒绝。
12. 作为使用者，我想粘贴 `api.github.com` 或 `codeload.github.com` 地址时被明确拒绝。
13. 作为使用者，我想粘贴带 `refs/heads/` 的 raw 地址也能被正确识别，因为我不一定记得去掉它。
14. 作为使用者，我想粘贴旧式 `github.com/{owner}/{repo}/raw/{ref}/{path}` 也能被识别。
15. 作为使用者，我想粘贴不带锚点的 gist 页面地址也能得到可下载地址。
16. 作为使用者，我想粘贴 gist raw 直链（带或不带文件名）都能被识别。
17. 作为使用者，我想在 gist 结果下方看到「仅适用于单文件 gist」的提示，这样我知道多文件 gist 只会有第一个文件。
18. 作为使用者，我想粘贴 release 资产地址时只看到支持它的 6 个前缀拼接式服务。
19. 作为使用者，我想粘贴 archive zip 地址时只看到支持它的服务。
20. 作为使用者，我想同一文件的不同写法（`blob` 页与 `raw` 直链）被识别为等价并标注，这样我知道自己重复粘了。
21. 作为使用者，我想源地址里多余的 fragment 和 `?raw=true` 被自动清理，这样复制出去的地址是干净的。
22. 作为使用者，我想其他查询串被原样保留，这样带 token 的地址不会被我改坏。
23. 作为使用者，我想生成的路径重排地址总是带明确的 ref，这样它不依赖服务端对「最新版本」的解析行为。
24. 作为使用者，我想在输入框下方展开查看支持的 6 类地址格式与示例，这样我偶尔忘了 `archive` 的确切形状也能查。
25. 作为使用者，我想粘贴错误格式时看到精确原因（例如「这是 tree 目录页，不支持」），而不是笼统的「格式错误」。
26. 作为使用者，我想在手机上使用这个页面，这样我在手机上转订阅地址时不用开电脑。
27. 作为使用者，我想把页面存成本地文件双击打开也能用，这样断网时仍能转换地址。
28. 作为使用者，我想通过一个开关决定是否显示 jsDelivr 的三个备用入口，默认不显示，这样结果列表不会被冗余行撑长。
29. 作为使用者，我想粘贴文本里的空行被忽略，这样带空行的文本不会产生无意义报错。
30. 作为使用者，我想主机名大小写不同（如 `GitHub.com`）也能被识别。
31. 作为使用者，我想看到每条加速地址的完整文本而不是被截断的中间态，这样我能确认最终内容。
32. 作为使用者，我想结果里重复出现的等价源地址仍然各占一张卡片，这样「我粘了几条就出几张」的预期不被破坏。

## Implementation Decisions

**产品形态**：纯静态单页。TypeScript + Vite 构建，用单文件插件把产物打成**一个自包含 HTML**，既可发布到 GitHub Pages，也可本地双击打开。不使用后端、不使用数据库、不发起任何运行时网络请求。

**唯一接缝**：`convert(text) → ConversionResult`。输入是输入框的原始文本，输出是渲染所需的全部内容：每张卡片对应的源地址、该卡片应出现的服务行、每行的加速地址、每条源地址的错误类型、等价源标注、以及每个服务的能力标签。界面层只渲染，不含任何判断逻辑。

**服务注册表**是扁平数据，每条记录包含：标识、显示名、端点、地址语法、是否去掉协议前缀、支持的能力集合。新增服务只加数据，不改逻辑。当前 8 条：

| 端点 | 地址语法 | 协议前缀 | 支持 |
| --- | --- | --- | --- |
| `cdn.jsdelivr.net` | 路径重排 | — | 仓库单文件 |
| `cdn.jsdmirror.cn` | 路径重排 | — | 仓库单文件 |
| `gh-proxy.com` | 前缀拼接 | 去掉 | 全部四类 |
| `ghproxy.net` | 前缀拼接 | 保留 | 全部四类 |
| `ghfast.top` | 前缀拼接 | 保留 | 全部四类 |
| `ghproxy.icu` | 前缀拼接 | 保留 | 全部四类 |
| `fastgit.cc` | 前缀拼接 | 保留 | 全部四类 |
| `github.chenc.dev` | 前缀拼接 | 去掉 | 仓库单文件、release 资产、归档包 |

jsDelivr 的三个官方备用入口（`fastly.jsdelivr.net`、`gcore.jsdelivr.net`、`testingcf.jsdelivr.net`）为同一地址语法的成员，由一个默认关闭的开关统一增删。

**能力集合与源类型的对应**固定为：仓库单文件 → 全部 8 个（含开关打开时的备用入口）；gist 直链 → 5 个（两个路径重排式服务无法承载 gist，`github.chenc.dev` 也不支持，实测 400）；release 资产 → 6 个前缀拼接式；归档包 → 6 个前缀拼接式。

**归一化**把源地址分成四类源类型，并产出 `{owner, repo, ref, path}` 四元组或 `{user, gistId}` 标识：
- 仓库单文件：`blob`、旧式 `/raw/`、`raw.githubusercontent.com` 三种输入统一成四元组，重建为 `raw.githubusercontent.com` 直链。
- gist 直链：页面地址落成 `gist.githubusercontent.com/{user}/{id}/raw`，不反推锚点、不枚举文件、不调用 GitHub API。
- release 资产与归档包：没有直链形态，以原地址透传给前缀拼接式服务。

**归一化的清洗规则**：剥离 `refs/heads/` 与 `refs/tags/` 前缀但保留其后的 ref 名；丢弃 fragment；丢弃 `?raw=true`；其余查询串原样透传。路径重排地址一律显式带 `@ref`。

**拒绝的输入**：`tree` 目录页、`api.github.com`、`codeload.github.com`、仓库首页、非 GitHub 域名、无法识别的路径形状。每种给出一条独立的错误类型，界面据此显示具体原因。

**等价判定**：两条源地址归一化后标识相同即视为等价，两条都保留并各自成卡，在后出现的那张上标注它等价于第几条。

**输出**：纯文本，一行一条加速地址；不做 Markdown 表格、不做 JSON。

**界面**：多行输入框（一行一条）→ 逐条卡片 → 卡片内扁平服务行（加速地址 + 复制 + 打开 + 能力标签）→ 每卡「复制本组」+ 页面级「复制全部」。输入框下方是可折叠的格式说明（6 类形状与示例），错误提示精确到类型。页面底部是完整支持矩阵参考表。

## Testing Decisions

**好测试的标准**：只断言外部行为——给一段文本，断言输出的卡片数、每张卡片的服务集合、每条加速地址的确切字符串、以及错误类型。不断言内部函数的调用、不检查 DOM 结构、不依赖网络。

**被测模块**：只有 `convert`。服务注册表作为数据被间接覆盖，因此新增服务时不需要新增测试。

**测试形式**：表驱动。每个用例是「一段输入文本 + 期望的卡片数组」。输入一律使用本次核实过的真实地址形态，期望值写成完整字符串，这样语法写错会立刻暴露。

**必须覆盖的用例**：四类源类型各至少一条；六种拒绝类型各一条；`refs/heads/` 剥离；`?raw=true` 丢弃与未知查询串保留；fragment 丢弃；等价源标注；空行忽略；主机名大小写；同一段文本里混排多类源；gist 页面与 gist raw 两种输入产出相同结果。

**前例**：仓库目前没有代码也没有测试，这是第一处测试设施，用 Vitest 作为唯一测试运行器。不引入浏览器测试、不做覆盖率门槛。

## Out of Scope

可用性检测与探活、历史记录、从列表站动态拉取服务、Markdown 或 JSON 输出、自定义域名、非 GitHub 源（GitLab 等）、`tree` 目录页、`api.github.com` 与 `codeload.github.com`、`git clone` 地址、多文件 gist 的文件枚举、gist 锚点的文件名反推、服务端渲染或任何后端逻辑。

## Further Notes

支持矩阵是 2026-11-16 在单一网络出口、用 `curl` 逐格实测的结果，这类服务的生命周期很短，矩阵会腐烂；注册表之所以做成纯数据，就是为了让更新成本只有改数据。

`ghproxylist.com` 被排除在注册表之外：它是收录代理的列表站，本身不是加速端点，把 GitHub 地址拼在它后面只会返回它自己的网页。

「语法家族 → 成员」的两层抽象被主动放弃，理由记录在 ADR-0001：共享构造器留在代码里，但不上升为数据模型与界面结构。
